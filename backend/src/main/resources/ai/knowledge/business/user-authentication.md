# 用户注册与登录

## 会话机制

认证基于 HTTP 会话：登录成功后在服务端会话中保存用户 id，浏览器通过 JSESSIONID Cookie 维持会话。除注册、登录外的接口都要求已登录，未登录返回 401。会话 Cookie 默认 HttpOnly、SameSite=Lax，生产环境可开启 Secure。

## 注册规则

POST /api/users 创建用户：
- username：1-50 个字符，只允许任意语言的字母、数字、组合字符以及 _、-、.
- password：只允许英文字母（a-z、A-Z）、数字、下划线
- 用户名已存在返回 409
- 注册不会自动登录，注册后前端会再调用登录接口

## 密码存储

密码从不以明文存储，也不在任何接口中返回。存储格式为 PBKDF2-SHA256（PBKDF2WithHmacSHA256，210,000 次迭代、16 字节随机盐、256 位密钥），编码为 pbkdf2-sha256$迭代次数$盐$哈希 的字符串，校验时用恒定时间比较防止时序攻击。

## 登录与登出

- POST /api/auth/login：校验用户名密码，成功后建立会话；失败返回 400「用户名或密码错误」
- POST /api/auth/logout：销毁会话
- GET /api/auth/me：返回当前登录用户，未登录时返回 {"user": null}

## 数据隔离

每个被监控的 URL 都属于一个用户。所有 URL、检查、时间线接口都只操作当前登录用户自己的数据；请求别人的 URL id 与请求不存在的 URL 一样返回 404，系统不会泄露该资源是否存在。
