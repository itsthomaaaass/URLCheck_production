# 内容变化检测

## 基本原理

URLCheck 通过比较网页内容的 SHA-256 哈希来判断内容是否发生变化。每次检查时，后端请求被监控的网页，对响应内容计算 SHA-256 哈希，再与上一次成功检查时保存的哈希（基线）比较：哈希不同就判定内容已变化，相同则判定没有变化。

## 哈希的计算方式

哈希由 ContentHasher 计算：边读取响应体边更新摘要（8 KB 缓冲区，恒定内存），最多读取 2 MiB。响应体超过 2 MiB 时只哈希前 2 MiB，超出部分的变化无法被发现——这是有意为之的性能限制。

只有 HTTP 状态码为 2xx 或 3xx 的响应才计算哈希；4xx/5xx 或网络错误不计算哈希，也绝不会被判定为内容变化。

## 判定规则

| 上次状态 | 本次探测 | 产生的事件 | changed |
| --- | --- | --- | --- |
| 没有保存的哈希 | 成功 | FIRST_CHECK | true |
| 哈希相同 | 成功 | 无事件 | false |
| 哈希不同 | 成功 | CONTENT_CHANGED | true |
| 任意 | 4xx/5xx 或网络错误 | UNAVAILABLE（每次故障只记一次） | null |
| DOWN | 成功 | RECOVERED | true |

检查失败时 changed 为 null 而不是 false。故障期间上一次成功的内容哈希会被保留，网站恢复后仍有东西可以比较。即使恢复时内容与之前完全相同，RECOVERED 也永远是一条独立事件。

## 一次故障只记录一个事件

网站从可用变为不可用时记录一个 UNAVAILABLE 事件；在它保持 DOWN 期间，后续失败的检查只刷新 last_http_status 和 last_error_type，不再追加事件。因此一个持续返回 403 或一直超时的网站只产生一条时间线记录，而不是每次检查一条。

## 已知限制

- 动态内容：哈希针对原始响应体计算，页面上有时间戳、随机数（nonce）、轮播广告等动态内容时，几乎每次检查都会报告 CONTENT_CHANGED。HTML 归一化、CSS 选择器监控等属于未来功能。
- 2 MiB 之后的内容变化不可见（见上）。
- 403 被记录为 UNAVAILABLE，含义是「系统无法读取该页面」，不代表网站真的宕机。
